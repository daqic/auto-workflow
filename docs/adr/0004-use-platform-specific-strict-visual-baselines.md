# Use platform-specific strict visual baselines

The runtime's desktop visual source is Penpot file `UI` (`40e06342-8830-80d6-8008-9359c0bc8bd4`), page `Dark` (`33d590fa-37fc-8099-8008-94e85b8e88bc`), revision `33`. The complete visual-regression boundary comprises the full-page `Sepolia Tool · Ready` board and the twelve additional state boards named by specification issue #12. The Ready image is captured at a fixed `1280 × 900` viewport; state images use the smallest stable user-visible component region containing each complete state. Visual tests continue to drive the public `/` route and intercepted Sepolia RPC requests rather than introducing an application-state injection seam.

Screenshots use the locally bundled Inter variable font and a version-pinned Playwright Chromium. Animations are disabled for capture. Baselines are stored in separate `darwin` and `linux` paths because platform font rasterization differs, and Linux candidates are generated and checked in the version-matched Playwright `v1.62.1-noble` environment used by CI. Comparisons retain Playwright's default perceptual color threshold and do not add a differing-pixel count or ratio allowance. A mismatch must fail the browser gate and retain expected, actual, and difference evidence.

Generated images are candidates until a human explicitly approves them; generating or committing a candidate does not approve it. An intentional design change requires confirming the applicable Penpot/specification revision, regenerating the affected platform candidates with the pinned environments, reviewing the image differences, and obtaining explicit human approval before treating the replacements as accepted baselines. Normal CI compares existing images and never updates them automatically.
